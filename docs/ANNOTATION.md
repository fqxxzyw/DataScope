# DataScope Annotation Workspace

数据标注是现有 DataScope 的一级功能，与分析、整理、格式转换和划分并列。不会修改原始数据；所有训练数据均另存为新文件。

## 使用流程

1. 打开「数据标注」→「新建标注项目」。导入 CSV / TSV / TXT / JSON / JSONL，或使用当前导入的数据。
2. 文件夹扫描先选择文件名，例如 `raw.json` 或 `processed.json`。程序显示文件数量与相对路径，避免同一帖子重复读取。单个 JSON 对象会适配为一条记录，复用 DataScope 解析器；数组和 JSONL 正常读取。
3. 预览原数据，选择主显示字段、辅助字段、唯一 ID。查看空标题、重复标题、唯一数量、平均长度、最长与最短标题。
4. 确认本地保存方式，创建项目。在「标签管理」新增任意标签、颜色、说明、数字快捷键，拖动或用上下按钮排序。
5. 点击标签或按 1–9 标注。保存成功后自动进入下一条，可关闭自动跳转。
6. 按状态、标签筛选，搜索标题 / 辅助正文 / ID。统计页提供标签分布、最近操作和随机抽查。
7. 导出训练 ZIP 或衔接 DataScope 原有数据集划分。

## 页面与组件

`src/annotation/Annotation.tsx` 管理项目列表和恢复；`ImportProject.tsx` 扫描与字段选择；`Workspace.tsx` 双栏标注、列表与统计；`LabelManager.tsx` 独立居中标签管理弹窗；`ExportPanel.tsx` 导出与备份。
业务纯函数在 `core.ts`，事务在 `db.ts`，状态操作在 `useProject.ts`，快捷键单独封装于 `useShortcuts.ts`，文件扫描使用 `scan.worker.ts`。复用已有 parser、ECharts、下载函数、ZIP 写入器和分层划分算法。

## 数据结构与保存

IndexedDB 数据库 `datascope-annotation`，版本 1：

| Store | 内容 |
|---|---|
| annotationProjects | 项目名称、字段、标签、来源说明、当前位置 ID、筛选、进度、revision |
| annotationSources | 本地工作副本，源字段的原始值与相对路径 |
| annotationRecords | `(projectId, recordId)` 复合主键；`labels: string[]`、status、updatedAt |
| annotationHistory | 操作、记录 ID、修改前后标注、时间、撤销状态 |
| annotationSessions | 会话开始时间、最后成功保存时间、操作次数 |

为关闭后直接继续，本模块在用户确认后保存源数据的**本地工作副本**。这不同于 ContextMap 的“只保存聚合摘要”。不保存浏览器 File 临时句柄，不修改磁盘源文件，不上传服务器，不将语料写入 localStorage。删除项目会清除其全部本地数据；请先备份重要项目。

普通标注写入当前记录、历史、项目进度、恢复位置与会话信息的**同一个事务**，不每次重写全部原始数据。事务成功才显示「自动保存 ✓」。写入失败保留上次成功状态并显示错误。通过 revision 检查拒绝另一个窗口的过期写入；冲突时重新打开项目，而不静默覆盖。

## 唯一 ID 与更新数据源

优先选择 `post_id` 等稳定字段。空 ID、重复 ID 会阻止创建 / 更新并列出冲突 ID，不按数组位置覆盖。
没有 ID 时可用完整记录内容的 SHA-256，键顺序规范化；内容改变会产生新 ID，完全相同的记录报告重复。建议长期项目使用业务唯一 ID。

更新时显示已有、新增、缺失和内容改变数量，经确认才写入。同 ID 且内容未变的标注保留；新增为未标注；内容改变的记录转回未标注，原标注存入历史。缺失记录的标注保留在备份中，不进入当前训练导出。备份不含源数据时无法核验旧正文变化，重新关联前应确认来源一致。

## 动态标签与快捷键

标签采用稳定内部 ID，所以改名不导致标注错位。名称不可重复，数字快捷键不可冲突。删除正在使用的标签时，明确选择映射到另一标签、取消这些标注或取消删除；不会默默丢失标注。颜色仅用于 UI，不进入训练数据。

- 1–9：标签。
- ← / Backspace：上一条；→：下一条。
- Space：标记 skipped。
- Ctrl+Z / Cmd+Z：撤销最近一次普通标注 / 跳过，持久保存撤销结果。
- Enter：确认当前已有标签；F：展开 / 收起正文。

输入框、下拉框、可编辑文本和标签管理弹窗内不触发。按钮上的 Enter / Space 保留按钮原生行为；可点击文章区域再使用快捷键。统计页的批量清空、标签删除、数据源更新不属于单条撤销操作；操作前可备份。

## 导出

只导出当前源数据里已人工标注的记录：

- 原始 JSON + label：保留原字段及嵌套值；原数据已有 label 时阻止覆盖，提示改用其他格式。
- JSONL / CSV：text、label；正文支持 `[title]`、`[content]` 模板组合。
- fastText：`__label__标签 正文`；标签含空白时报告错误，正文换行合并为空格。
- BERT ZIP：train.tsv / dev.tsv / test.tsv / class.txt；复用分层划分，80/10/10，seed 42，标签编号按当前顺序从 0 开始。小类别不足时以实际划分为准，警告保存在 split-info.json。
- 所有训练 ZIP 包含按当前标签顺序排列的 class.txt。
- 「进入 DataScope 数据集划分」可自定比例与方法，再沿用格式转换流程。

项目备份默认只含项目设置、标签、annotations 和当前位置；可主动勾选包含源数据。恢复创建独立项目副本，不覆盖现有项目。未带源数据时通过「更新数据源」重新关联。

## 性能与边界

扫描限 20,000 文件、200 MB、100,000 记录。只渲染当前文章和分页结果（每页 40），不渲染全部语料 DOM。正文默认前 800 字，支持展开。目录只展示前 200 个相对路径，但扫描使用全部所选文件。JSON / JSONL 文件解析在 Worker，支持取消；项目身份校验异步执行。

已实现：单标签文本 / 文章分类、动态标签、鼠标与快捷键、跳过、单条撤销、自动保存、进度、筛选、搜索、随机抽查、修改历史、恢复、备份、导出和划分衔接。

仅预留：多标签数组、predictedLabels 与 prediction 字段；预测结果不会自动成为人工标注。未实现 NER、QA、图像标注、AI 预标注、低置信度排序和模型训练，不依赖任何在线 API。

## 验证

`npm run lint`、`npm test`、`npm run build`（含 TypeScript strict 检查）。Vitest 验证稳定 ID、重复冲突、标签规则、状态计数、导出、备份及真实 IndexedDB 接口事务 / 版本冲突（fake-indexeddb）。Playwright 验证 JSON 与文件夹导入、键盘标注、跳过筛选、撤销、刷新恢复、修改、导出和新增数据关联。Windows 工作流继续构建和检查实际 EXE。
